# Banner Video Implementation

This document explains how the banner video on `/home-page` was created using the AEM Embed block and an MP4 asset authored from DAM.

## Overview

The banner video is not a separate custom block. It is an Embed block placed inside a section with the `banner-video` class. The implementation has three parts:

1. The Embed component model lets the author select a DAM video.
2. `blocks/embed/embed.js` detects MP4 URLs and renders a native HTML `<video>` element.
3. `blocks/embed/embed.css` styles the Embed block when it is inside the banner-video section.

The published page uses this authored DAM asset:

```text
/content/dam/kotak-life/assets/video/intro_desk.mp4
```

## Authoring Steps

1. Open the `/home-page` page in the editor.
2. Add an Embed component to the section that will contain the banner video.
3. In the Embed component, select or enter the MP4 asset from DAM in the `Embed URL or DAM Video` field.
4. On the containing section, add the class `banner-video`.
5. Add `autoplay` to the section when the video should start automatically.
6. Add `hide-control` to the section when the native video control bar should not be shown.
7. Preview or publish the page.

The resulting section can look like this in the rendered DOM:

```html
<div class="autoplay hide-control section banner-video">
  <div class="embed-wrapper">
    <div class="block embed embed-mp4">
      <!-- The video element is generated by embed.js. -->
    </div>
  </div>
</div>
```

The exact wrapper elements can vary depending on the page decoration and editor output. The important part is that the Embed block is inside an element with the `section` class, and that the section also contains the desired behavior classes.

## Embed Model

The model is defined in `blocks/embed/_embed.json` and is included in the project component configuration through the generated JSON files.

The authoring fields are:

| Field | Purpose |
| --- | --- |
| `image` | Optional placeholder image shown before the embed is loaded. |
| `imageAlt` | Alternative text for the placeholder image. |
| `link` | The external embed URL or the DAM MP4 reference. |

For a banner video, the `link` field is the important field. The MP4 can be authored as an internal DAM path such as `/content/dam/kotak-life/assets/video/intro_desk.mp4`.

## JavaScript Behavior

The Embed block is implemented in `blocks/embed/embed.js`.

### 1. DAM URL resolution

A DAM path beginning with `/content/dam/` is converted to the configured AEM Publish domain:

```js
https://publish-p48457-e1275402.adobeaemcloud.com/content/dam/...
```

This is necessary because the Edge Delivery preview URL does not necessarily serve the AEM DAM asset directly. The publish domain is the environment configured for this project in `fstab.yaml`.

### 2. MP4 detection

The Embed block checks the authored URL for `.mp4`. When it finds an MP4, it calls `embedMp4()` instead of creating an iframe.

The generated element is a native video player:

```html
<video src="..."></video>
```

### 3. Section behavior classes

During decoration, the Embed block finds its containing AEM section with:

```js
const section = block.closest('.section');
const autoplay = section?.classList.contains('autoplay');
const hideControls = section?.classList.contains('hide-control');
```

AEM renders sections as elements such as `<div class="section ...">`, so the lookup must use `.closest('.section')`, not `.closest('section')`.

These values are passed into the MP4 renderer:

```js
loadEmbed(block, link, autoplay, hideControls);
```

The renderer applies the video attributes as follows:

- `autoplay`: adds `autoplay muted loop playsinline`.
- `hide-control`: omits the `controls` attribute.
- Neither class: adds `controls` so the visitor can use the native player controls.

When both classes are present, the expected output is equivalent to:

```html
<video
  src="https://publish-p48457-e1275402.adobeaemcloud.com/content/dam/kotak-life/assets/video/intro_desk.mp4"
  autoplay
  muted
  loop
  playsinline>
</video>
```

## CSS Behavior

The banner-video styles are currently in `blocks/embed/embed.css` because the visual element is an Embed block.

The main selectors are:

```css
.section.banner-video,
.section.banner-video * {
  min-height: 670px;
  max-height: 670px;
  height: 670px;
}

.section.banner-video .embed-wrapper,
.section.banner-video .embed {
  max-width: 100%;
  padding: 0;
}
```

These rules make the banner video fill the banner area and override the Embed block's normal `800px` maximum width. The first-section rule also offsets the banner when it appears below the header:

```css
main > .section:first-of-type.banner-video {
  margin: -96px 0 0;
}
```

The Embed block itself uses a 16:9 responsive wrapper by default. The banner-video height rule intentionally replaces that default sizing with a fixed 670px banner height.

## Browser Autoplay Requirement

Modern browsers generally allow autoplay only when the video is muted. For that reason, the `autoplay` class adds all of these attributes:

```html
autoplay muted loop playsinline
```

`muted` is required for reliable autoplay, and `playsinline` prevents mobile browsers from forcing the video into a full-screen player. If audio is required, the visitor must start the video through an explicit user interaction.

## Validation Checklist

- Confirm the Embed component's `link` field points to the intended `.mp4` DAM asset.
- Confirm the containing element has the `section` class.
- Add `banner-video` for banner sizing.
- Add `autoplay` for muted automatic playback.
- Add `hide-control` to remove the native controls.
- Check the rendered markup for `embed-mp4`.
- With autoplay enabled, confirm the video contains `autoplay`, `muted`, `loop`, and `playsinline`.
- With hide-control enabled, confirm the video does not contain `controls`.
- Confirm the resolved publish URL responds as `video/mp4`.
- After code changes, preview the updated branch and refresh the page without a stale browser cache.

## Files Involved

- `blocks/embed/_embed.json`: Embed authoring model and component definition.
- `blocks/embed/embed.js`: DAM URL resolution, MP4 rendering, and section-class behavior.
- `blocks/embed/embed.css`: Embed styling and banner-video layout rules.
- `fstab.yaml`: AEM environment mapping used to identify the publish environment.
